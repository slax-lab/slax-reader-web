# Question Patterns — review-slax-web

何时用 `AskUserQuestion` 工具问开发者？以下是典型场景。

**记住**：意图不明、有多种实现可能、框架行为差异、fork/upstream 归属不清 —— 都该问，不要瞎猜。

---

## 提问的硬性原则

1. **分轮问** —— 每轮 2-4 个最关键的问题，等回答完再下一轮。
2. **给选项，不开放式** —— 用 `options` 数组（2-4 个）。
3. **附 (Recommended)** —— 更可能的选项放第一位，label 末尾加 `(Recommended)`。
4. **header 要短** —— ≤ 12 字符 chip，例如 `"响应式"`, `"归属"`, `"SSR"`, `"i18n"`, `"同步"`。
5. **影响结论的优先**。

---

## 典型问题场景

### 0. 上下文与规范（阶段 0 专用）

> **拿不到 PR 需求描述**

- "这次改动的需求/目的是什么？解决什么问题？"
  - 选项：`"修 bug"` / `"加新功能"` / `"重构 / 优化"` / `"样式/主题调整"`

> **子 agent 偏好**

- "要不要起子 agent 找更最小化的写法 / 更该复用的既有组件/composable？"
  - 选项：`"要，重点找复用&最小化 (Recommended)"` / `"不用，按现有写法审"` / `"只在大改动组件上找"`

### 0.3 联动（fork/monorepo 专用）

> **改了 upstream layer / commons**

- "这次动了 upstream layer / commons 包，会影响 web + extension 双端 / 后端契约 —— 相关项目加进工作区了吗？"
  - 选项：`"已加入，可扫联动 (Recommended)"` / `"没加，先加上再继续"` / `"跳过联动检查，报告标 Open Item"`

---

### 1. fork / upstream 归属

> **改到了 fork 但可能应改上游**

- "这个组件改在了 fork `app/`，但它看起来是通用逻辑 —— 是有意 fork 分叉（Pro 差异），还是应该改 upstream layer 让两端都受益？"
  - 选项：`"有意 fork 分叉"` / `"应该改 upstream (Recommended)"` / `"不确定，帮我判断"`

> **新增整份 override**

- "这里整份 copy 了 upstream 组件做 override，只为少量 Pro 差异 —— 能否改用 slot/props 减少未来漂移？"
  - 选项：`"能，改成组合"` / `"不能，差异太大必须整份覆盖"` / `"先这样，后续再说"`

---

### 2. 响应式 / 渲染

> **解构可能丢响应性**

- "这里解构了 props/store，后面 watch/computed 依赖它 —— 是确定该值不变，还是疏漏了响应性（应 toRefs/storeToRefs）？"
  - 选项：`"疏漏，应保留响应性 (Recommended)"` / `"该值确定不变"` / `"不确定"`

> **watcher 未清理**

- "这个 setInterval/addEventListener 没在 onUnmounted 清理 —— 组件会多次挂载吗？"
  - 选项：`"会，必须清理 (Recommended)"` / `"单例，不会重复挂载"` / `"改用 VueUse 自动清理"`

> **大列表无虚拟滚动**

- "这个列表预期多少条？超过一屏很多要不要虚拟滚动/分页？"
  - 选项：`"通常很少"` / `"可能很多，需要虚拟滚动 (Recommended)"` / `"不确定"`

---

### 3. SSR / Hydration

> **setup 顶层用了浏览器 API**

- "这里在 setup 顶层用了 window/localStorage —— SSR 时会 hydration mismatch，是有意只跑客户端吗？"
  - 选项：`"疏漏，应放 onMounted/ClientOnly (Recommended)"` / `"这页只 CSR"` / `"不确定"`

> **useState vs 模块级 ref**

- "这个跨组件状态用了模块级 `ref` —— SSR 下会跨请求泄漏，要不要换 `useState`？"
  - 选项：`"换 useState (Recommended)"` / `"纯客户端无所谓"` / `"不知道这个坑"`

---

### 4. 边界 / 数据

> **可能为空**

- "这个数据可能为 null/空数组吗？（首次进入、离线、接口失败）当前渲染分支覆盖了吗？"
  - 选项：`"覆盖了"` / `"没覆盖，应加空态 (Recommended)"` / `"不确定"`

> **`||` vs `??`**

- "这里 `x || default`，x 为 0/''/false 时也会兜底 —— 是想要的吗？"
  - 选项：`"不是，应用 ?? (Recommended)"` / `"是的，空值也兜底"` / `"不确定"`

---

### 5. 本地优先 / 同步

> **乐观更新无回滚**

- "这里先写本地再同步后端，同步失败怎么处理？UI 乐观态要回滚吗？"
  - 选项：`"要回滚 (Recommended)"` / `"失败也保留本地，稍后重试"` / `"没想清楚"`

> **离线态**

- "这个操作在离线时会怎样？调后端 API 直接失败还是有降级？"
  - 选项：`"有离线降级"` / `"没考虑离线 (Recommended 补)"` / `"这功能不支持离线"`

---

### 6. 样式 / i18n

> **硬编码颜色**

- "这里硬编码了颜色而非用 `--slax-*` token —— light/dark/eink 三主题会漂移，是临时值吗？"
  - 选项：`"疏漏，应用 token (Recommended)"` / `"确实只在一个主题用"` / `"临时占位"`

> **文案硬编码**

- "这段用户可见文案硬编码了 —— 要走 i18n 吗？（Dashboard 内部页面除外）"
  - 选项：`"要走 i18n (Recommended)"` / `"这是 Dashboard 内部页，免 i18n"` / `"临时文案"`

---

### 7. 三方依赖 / 升级

> **升级核心依赖**

- "这次升了 Nuxt/Vue/UnoCSS/VueUse 版本 —— 看过 changelog breaking changes 了吗？"
  - 选项：`"看了，无影响"` / `"看了，有迁移（已做）"` / `"没看，靠测试覆盖"`

---

## 不要这样问

- "看起来 OK 吗？"（太开放）
- "你觉得应该怎么改？"（review 不是把判断推给用户）
- 一次问 10 个问题
- 问纯文档型问题（"Nuxt useFetch 怎么用？"——自己搜）

---

## 好提问 vs 差提问

| 差               | 好                                                              |
| ---------------- | --------------------------------------------------------------- |
| "这里有问题？"   | "解构了 store，后面 watch 依赖它，是丢了响应性还是该值不变？"   |
| "为什么这样写？" | "setup 顶层读 localStorage，SSR 会 mismatch，是有意只 CSR 吗？" |
| "性能够吗？"     | "这个列表预期多少条？超一屏很多要不要虚拟滚动？"                |

## 问完之后

每轮 Q&A 都记录到最终报告「用户对话记录」。用户回答过的不要又当「待确认」列出。
